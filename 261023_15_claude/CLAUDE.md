# P_CLAUDE.md — 개발자 지역 지침

모든 프로젝트에 공통으로 적용하는 작업 원칙. 프로젝트별 CLAUDE.md 가 이 문서와 충돌하면 **프로젝트 지침이 우선**한다.

## 1. 소통

| 항목 | 규칙 |
|------|------|
| 언어 | 한국어로 답한다. 코드 식별자·기술 용어는 원문 유지 |
| 길이 | 결론 먼저, 근거는 짧게. 불필요한 서론·요약 반복 금지 |
| 질문 | 코드·문서로 확인 가능한 건 묻지 말고 직접 확인. 정말 사용자 결정이 필요할 때만 질문 |
| 보고 | 테스트 실패·건너뛴 단계는 숨기지 않고 그대로 보고 |

## 2. 작업 범위

- 요청받은 것만 고친다. 리팩토링·추상화·기능 추가는 먼저 제안만 한다.
- 기존 코드의 스타일(네이밍·주석 밀도·들여쓰기)을 따른다.
- 새 파일보다 기존 파일 수정을 우선한다.
- 문서(README 등)는 요청이 있을 때만 만든다.

## 3. 코드 작성

| 원칙 | 내용 |
|------|------|
| 단순함 | 지금 필요한 만큼만 구현. 가상의 미래 요구를 위한 설계 금지 |
| 주석 | "무엇"이 아니라 "왜"가 필요한 곳에만 |
| 에러 처리 | 실제로 일어날 수 있는 경계(입력·네트워크·파일)에서만 |
| 비밀 정보 | API 키·비밀번호를 코드에 하드코딩하지 않는다. `.env` + `.gitignore` |
| 의존성 | 새 라이브러리 추가 전 기존 의존성으로 해결 가능한지 확인 |

## 4. 검증

- 수정 후 반드시 실행하거나 테스트로 확인한다. "아마 될 것"으로 끝내지 않는다.
- 버그 수정은 원인을 찾고 고친다. 증상만 가리는 우회는 그 사실을 명시한다.
- 검증하지 못했다면 "검증 못 함"이라고 명확히 쓴다.

## 5. Git

| 항목 | 규칙 |
|------|------|
| 커밋 | 의미 있는 작업 단위로. 메시지는 `type(scope): 한국어 제목` |
| push | **명시적 지시가 있을 때만** |
| 브랜치 | 기본 브랜치에서 큰 작업을 할 땐 새 브랜치 생성 |
| 금지 | 지시 없는 `--force`, `reset --hard`, hook 우회(`--no-verify`) |

## 6. 위험한 작업

삭제·덮어쓰기·배포·외부 전송처럼 되돌리기 어려운 작업은 **먼저 대상을 확인하고 사용자 승인을 받는다.**

## 7. 환경 (Windows)

- 셸 명령은 PowerShell / Git Bash 문법을 구분해서 쓴다.
- 경로에 공백이 있으면 따옴표로 감싼다.
- Python 출력 깨짐 방지: `PYTHONIOENCODING=utf-8`
